# Concierge person-request review contract

Source candidate only. Release requires `config/release-authority-policy.json`,
authenticated `pnpm release:authority:resolve`, exact-source disposition and
the required connected protected acceptance. This document enables nothing.

## Visitor contract

`/ask` and the existing four-lane widget expose Request a person without an AI
answer, account or interview. The secure follow-up form collects an editable
request, at least one supported contact method and the existing explicit
requested-response consent. Optional fields remain optional. Anonymous questions
still use the existing governed answer route and do not create a contact lead.
No provider/model configuration or answer-source permissions change.

The AI label identifies Our Town Properties, Inc. and disclaims human/broker
identity. Requesting a person cancels an outstanding answer; it does not claim
that staff joined. Manual intake works if chat is unavailable. The widget retains
the opened Ask panel across lane changes so its pending payload is not recreated.
Other lanes and the protected standalone fallback keep their existing contracts.

An uncertain save freezes the body, consent and key in the current document.
Retry sends identical bytes. No raw payload is written to browser storage.
A document reload is not a supported payload-recovery mechanism; keep an unresolved
form open. Different tabs retain their existing independent inquiry identities;
canonical same-contact duplicate holds remain authoritative, not bypassed.

Only a confirmed canonical save produces confirmation. Held, unknown-eligibility
and replay outcomes use neutral stored-for-review copy and hide the optional
conversation CTA. A fresh non-held save may offer existing preferences and an
explicit conversation request. Preferences are not new permission, live availability
or a confirmed booking; there is no calendar write or invitation in this slice.

## Server review policy and evidence

`app/lib/humanReviewPolicy.ts` is the one implementation. Daily coverage is
08:00 inclusive–20:00 exclusive America/New_York, including weekends, with a
five-covered-minute internal objective. Milliseconds carry without rounding a
target earlier. UTC instants and the IANA zone are retained; DST uses local-day
windows, not a fixed offset. A preferred callback date/window does not move review.

Explicit server-authored exceptions may close a day or reduce its windows for
holiday/vacation/no-staff/reduced coverage. None is invented or preinstalled.
Overlapping/invalid/expanded windows fail validation. A changed schedule needs
review and a new policy version; retain definitions for supported saved versions.
There is no new scheduling UI, live-presence service, timer or escalation transport.

After ingress and consent validation, new chat captures attach the policy version,
server acceptance instant, UTC target and zone to `human_review` metadata on the
existing atomic primary internal lead-alert intent. This is capture-operation
evidence, not a new send, task or queue. SQL exact retries return before inserting
or changing it. Transaction failure stores neither inquiry nor review evidence.
Server acceptance is not claimed to be the database commit instant; the original
database receipt/capture time remains visible separately.

Protected Today and inquiry detail use bounded, inquiry-scoped reads of that
metadata. No provider body/recipient snapshot is exposed. Existing RBAC, owner,
terminal, test, suppression and NO FOLLOW-UP rules remain authoritative. Held
records show internal-review-only copy, not an actionable contact deadline.
Missing historical evidence stays unknown. Existing task due dates are unchanged.
Covered wait and total age are distinct; target-passed is not proof of an absent
human review or response. Inspect the retained actual history before acting.

## Release, activation and recovery

No schema, environment, sender, recipient, B1/B2 cutoff, provider, calendar,
ownership, allocation, cron or campaign change is part of this candidate.
Original alerts and B1/B2 are never delayed by coverage. No history catch-up.
Broker-in-charge review of the customer-facing real-estate/agency boundaries
and source-bound application acceptance remain activation prerequisites.

Use the existing app-only release process with synthetic/fake-off connected
acceptance only under separately valid resource authority. Review publication
is not merge/deployment authority. The branch's explicit Vercel Git exclusion
prevents automatic application deployment while normal review CI still runs.
Compatible application recovery retains all additive metadata, records, consent,
task and delivery history. Never erase them to roll back presentation.

Verification: focused policy/component tests, the existing actual root-POST
PostgreSQL suite (including retained metadata/replay/RBAC), disconnected built
person-request/keyboard/reflow fixtures, and mandatory final hosted Release Gate.
Fixture screenshots and fake receipts are not live delivery or physical-device
acceptance. Genuine customer demand and human response require their own evidence.
